# 容器格式说明（对外版）

> 这份文档面向想理解或实现兼容工具的人。内部设计细节见仓库 `logs\` 目录。

## 文件头（v1 / v2 通用前缀）

所有整数**大端**。

```
magic[8]   "CBXFILE1"
ver        u8     1 或 2
algId      u8     1=AES-256-GCM  2=ChaCha20-Poly1305
kdfId      u8     1=PBKDF2-HMAC-SHA256
flags      u8     bit0 有名字 / bit1 跳过后缀检查 / bit2 有类别 /
                  bit3 类别=图片 / bit4 类别=其他 / bit5 名字已加密 / bit6 有批次 ID
chunkSize  u32
plainSize  u64
chunkCount u32
kdfIter     u32
saltLen    u8 + salt
nonceLen   u8 + baseNonce
nameLen    u16 + name（UTF-8，可能已加密）
```

v2 追加：

```
kind         u8   0=单文件 1=批量成员 2=归档
batchLen     u8 + batchId（批量成员专用，12 字节随机）
archiveFlags u8   bit0=允许预览（归档专用）
```

## 正文

每个数据块独立认证：

```
ctLen u32 | ciphertext | tag[16]
```

- nonce = baseNonce[0..7] ‖ BE32(chunkIndex)
- AAD   = SHA256(头部原始字节) ‖ BE32(chunkIndex)

也就是说：**改头部任何一位、改块顺序、截断文件，都会被检测到。**

## 归档（kind=2）

明文流是一段自定义归档：

```
manifestLen u32 | manifest JSON | 各条目内容（按清单顺序拼接）
```

清单形如 `{"Entries":[{"Path":"a.txt","Size":123}]}`。
解压时按清单顺序切分，因此可以只解出被选中的条目。

## 名字加密

名字可选加密。为避免「加密名字需要头部哈希、而头部又包含名字」的循环依赖，
名字的 AAD 单独定义为：

```
AAD = SHA256(salt ‖ baseNonce ‖ algId ‖ kdfId ‖ "CBXNAME1")
```

## 兼容性

- 读取端接受 v1 与 v2；写入端一律写 v2
- 算法编号一旦发布永不复用
